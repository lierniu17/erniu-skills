# 资源筛选与路线规划细则

目标不是「找很多好资源」，而是**在 5 个坑位各放一个，且每个都真的会被用掉**。

---

## 一、先定资源类型，再找具体资源

按「学到哪一层」选来源，别一上来就找视频：

| 目标 | 首选来源 | 为什么 |
|---|---|---|
| 建立结构 | 权威教材目录、认证大纲 | 结构被行业验证过（巨人学习法） |
| 快速跑起来 | 官方 quickstart / getting started | 作者保证能跑通，最短路径 |
| 理解机制 | 经典教材对应章节、综述文章 | 讲因果，不讲操作 |
| 形成技能 | 真实项目、开源仓库、案例拆解 | 有约束条件和取舍 |
| 补细节 | 官方 API 文档、标准、手册 | 唯一权威，当字典查不背 |
| 学判断力 | 领域顶尖者的长访谈、博客、复盘 | 给的是提问方式和取舍标准 |

---

## 二、去哪找（按类型）

- **官方文档**：项目官网 `/docs`、`/getting-started`、GitHub README 的 Examples。永远优先于二手教程。
- **系统课程**：Coursera / edX / MIT OCW / 国内慕课平台的**名校同名课**；看 syllabus 而不是看宣传页。
- **教材**：出版社官网目录页、豆瓣评分 8.5+ 且标注「第 N 版」的；优先选有习题和答案的。
- **实战**：GitHub `awesome-<领域>` 列表、官方 examples 目录、有完整 commit 历史的开源项目。
- **大师输出**：个人博客、会议演讲（如各语言/领域年度大会）、长播客、经典论文。判断标准是「有没有可验证的成果」，不是粉丝数。
- **中文补充**：技术类优先看官方中文文档；中文教程只用来破冰，不用来定标准。

**给链接前必须核实**：用 WebSearch / WebFetch 确认地址可访问、内容与描述一致、版本没过期。不要凭记忆写 URL。

## 三、评分与淘汰

4 维各 1–5 分，**总分 ≥16 入选**：

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| 权威性 | 官方/原作者/领域公认 | 知名博主、口碑课程 | 来源不明、二手拼凑 |
| 相关度 | 覆盖目标 80%+ | 覆盖一半，需自己拼 | 只沾边 |
| 时效性 | 近 1–2 年 / 版本仍是最新 | 3–5 年，主体仍成立 | 已弃用、API 全变 |
| 上手成本（分高=容易） | 打开就能跑 | 需配置环境 | 需先学三个前置 |

淘汰时写一句原因（"2019 年，API 已改"），避免下次又捡回来。

## 四、常见坑

- **教程地狱（tutorial hell）**：一直在跟教程走，离开教程什么都写不出。解药：第 3 个坑位必须是「没有答案的项目」。
- **资源囤积**：收藏 40 个 = 一个都不用。硬上限 5 个。
- **过期教程**：视频教程最容易过期。超过 2 年的操作类内容，先对照官方文档验证。
- **难度错配**：入门期读论文、进阶期看科普。按学习区选，不按名气选。
- **只看不练**：任何资源如果不能在 1 小时内产出东西，就把它降级为「参考」。

## 五、周路线生成规则

1. **周期**：默认 6 周（西蒙学习法的时间盒）。用户明确说 2 周或 6 个月，按他说的，但必须写死。
2. **切分**：一周一个一级模块，按地图依赖顺序排，不跳跃。
3. **每周四件事**（缺一不可）：学 2 个核心点 → 练一个小产出 → 讲 3 分钟给 AI → 闭卷测 5 题。
4. **缓冲**：6 周里留 1 周做「整合项目」，把前面模块串起来。
5. **可验证**：每周结束时能指着一样东西说「这是我做出来的」。
6. **不排满**：每周计划排到 70% 容量，剩下 30% 吃掉现实中的意外。

路线是日历式的（W1 做 X，W2 做 Y），不是目录式的（第 1–3 章）。
